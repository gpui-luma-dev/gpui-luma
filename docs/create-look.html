Create your own Look

Start with one control. Reuse its SDK behavior.

Start small

A Look can begin as an application helper. Keep your visual decisions together and return SDK control entities.

Local Look helper · integration snippet
use gpui::{prelude::*, Context, Entity, px};
use gpui_luma::controls::button::Button;
use gpui_luma::infra::presenter::HasPresenter;

fn action_button<M: 'static>(cx: &mut Context<M>) -> Entity<Button> {
    Button::new("action")
        .label("Continue")
        .with_template_modifier(|root, _| root.min_w(px(160.0)))
        .spawn(cx)
}

This customizes the fallback template’s geometry. It is a starting seam, not a complete visual system.

Inherit the SDK baseline

SDK-only applications and custom Looks can use CommonStylesheet::resolve_layers to inherit shared tokens, control geometry, icons and semantic state recipes. Configure only your differences, then capture a theme snapshot:

Rust · SDK theme snapshot
use gpui_luma::{
    color::GamutMapping,
    controls::progress::{DefaultProgressTheme, ProgressTheme},
    theme::{ControlSize, ThemeMode, stylesheet::CommonStylesheet},
};

fn configured_progress_theme() -> Result<DefaultProgressTheme, Box<dyn std::error::Error>> {
    let sheet = CommonStylesheet::resolve_layers(&[
        "[common.progress.sizes.md]\ntrack_height = 9",
    ])?;
    let tokens = sheet.theme_tokens(ThemeMode::Light, GamutMapping::CssLocalMinde)?;
    let theme = DefaultProgressTheme::new(tokens);
    assert_eq!(theme.resolve(true, ControlSize::Md).track_height, 9.0);
    Ok(theme)
}

Pass the theme to the existing SDK themed template. Existing snapshots keep their styling; rebuild themes after editing configuration. Missing values inherit, while zero remains an explicit override. Palette, metrics, typography and elevation are configured under common.tokens. The complete control/helper inventory records which layout and interaction constants remain in Rust. See the stylesheet contract for current coverage.

Change recipes without copying colors

Semantic recipe slots reference the shared palette. Missing fields inherit; zero, false and empty arrays remain explicit overrides.

TOML · custom look differences
[common.recipes.button]
"state.hover.background" = "state.selected.background"

[common.icons]
clear = "svg:icons/clear.svg"

[common.row_limits.combobox]
max = 10

[common.switch.sizes.sm]
track_width_scale = "math(32 / 28)"

Palette/shadow colors use hsla(h, s%, l%, a). Math uses floating-point division and is validated after evaluation. Explicit consumer icons, geometry and row limits override captured defaults. SDK themes capture snapshots; rebuild them after changing configuration. Motion keeps its existing independent snapshot policy.
