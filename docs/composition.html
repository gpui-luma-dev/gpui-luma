Composition & helpers

Shared renderers, popup hosting, and form composition helpers.

Shared rendering & hosting

These APIs help compose controls rather than supplying standalone interactive widgets.

  • Selector List: shared option-row and panel templates used by selection controls.
  • Floating Menu: menu state and rendering infrastructure used by popup and context menus; there is no standalone FloatingMenu entity.
  • Popup Scroll Surface: scroll hosting for popup rows, with a supplied scrollbar template.

Form helpers

declare_form! generates an owning struct and constructor that spawns its declared builders, stores arguments and fields, and retains optional event subscriptions. It does not generate the form’s rendered layout. Use Look builders for interactive controls.

form_field! places a label above a supplied control with a 4px gap; it uses the supplied chrome’s body text color. It is a layout helper, not a form-validation framework.

Rust
use gpui::{Context, Entity, prelude::*};
use gpui_luma::controls::button::Button;
use gpui_luma::{declare_form, form_field};
use gpui_luma::infra::presenter::HasPresenter;
use gpui_luma_look_shadcn as shadcn;

declare_form! {
    struct ExampleForm {
        controls: {
            save: Entity<Button> = shadcn::Button::new("save").label("Save")
        },
        args: {},
        fields: {}
    }
}

fn labeled_control(control: Entity<Button>) -> impl IntoElement {
    let look = shadcn::ShadcnLook::built_in();
    form_field!("Action", look.chrome(); control)
}

Create the owner with ExampleForm::new(cx) in its entity constructor; render the stored controls in the owner’s view. Optional event mappings in declare_form! use SDK event types and retained subscriptions.
