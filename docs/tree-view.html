Basic use

Radix · integration snippet
use gpui::{Context};
use gpui_luma_look_radix as radix;
use gpui_luma::controls::tree_view::TreeNode;

struct Example {
    control: gpui_luma::controls::tree_view::TreeView<()>,
    selected_nodes: std::collections::HashSet<gpui::SharedString>,
}

impl Example {
    fn new(cx: &mut Context<Self>) -> Self {
        let control = radix::TreeView::<()>::new("example")
            .items([
                TreeNode::new("workspace", "Workspace", ()).expanded(true).children([
                    TreeNode::new("src", "src", ()).expanded(true).children([
                        TreeNode::new("main", "main.rs", ()),
                        TreeNode::new("controls", "controls", ()).children([
                            TreeNode::new("button", "button.rs", ()),
                            TreeNode::new("input", "input.rs", ()),
                        ]),
                    ]),
                    TreeNode::new("assets", "assets", ()).children([
                        TreeNode::new("icons", "icons", ()),
                        TreeNode::new("fonts", "fonts", ()),
                    ]),
                    TreeNode::new("cargo", "Cargo.toml", ()),
                ]),
                TreeNode::new("docs", "Documentation", ()).children([
                    TreeNode::new("guide", "Getting started", ()),
                    TreeNode::new("reference", "API reference", ()),
                ]),
            ])
            .on_selection_changed(cx, |app, selected_ids, cx| {
                app.selected_nodes = selected_ids.clone();
                cx.notify();
            })
            .spawn(cx);

        Self { control, selected_nodes: Default::default() }
    }
}

Integration snippet, checked against the current SDK and Radix crates. cx is the initialized owner context. The control retains its callbacks; callback owners are held weakly. Render self.control.clone() in the owner’s view.

SDK behavior & customization

Rows own disclosure, selection, focus, and scrolling. Use Frame for optional outer decoration.

Relevant contracts: TreeViewRenderModel, TreeViewTemplateHandlers, TreeViewTemplateModifier, TreeViewTemplate.

Use the module’s template contract for structural changes. Builder modifiers and item templates vary by control.

Events

Callbacks follow the existing SDK event stream. Registrations append, hold the owner weakly, and live until the control is released. cx.notify() requests an owner redraw. Compound payloads are borrowed; scalar values are passed by value.

Drag/drop

See Drag and drop for the lifecycle, proposal/completion distinction, ordering, scopes, and callback ownership shared by these controls.

Enable drag_drop(TreeViewDragDrop::new(scope, on_drop)) on SDK, Shadcn or Radix builders. The handler receives TreeDropProposal<T>: call validate(cx), prepare both snapshots, apply the move and transferred selection/expansion state, then call committed(changed, cx) or rejected(error, cx). can_drop is admission policy for markers, auto-scroll and drop revalidation.

SDK TreeViewBuilder, TreeViewEventExt and both Look builders expose all seven named helpers through TreeViewEvent::DragDrop(TreeViewDragEvent). The domain payloads below replace the shared key/gap fields: node_ids is the normalized moving roots in displayed order, with selected descendants covered by their ancestor; node_id is the first root. Add/reorder/drop retain TreeDropLocation { parent_id, anchor_id, position }, including Into and After. Moves within a tree include reparenting.

Compatibility: Started, Dropped, Rejected, Ended and their callback signatures remain. Exhaustive enum matches must add ItemsRemoved, ItemsAdded, ItemsReordered arms or a wildcard. The historical TreeDragEndReason names map Reordered → MovedWithinTree and Transferred → MovedAcrossTrees.

on_drag_started / Startedsource: EntityId, node_id: &SharedString, node_ids: &Vec<SharedString>
on_items_removed / ItemsRemovedsource: EntityId, target: EntityId, node_id: &SharedString, node_ids: &Vec<SharedString>

Validate proposals and observe completion

Compiled by scripts/check_control_docs.py.

mod drag_drop_example {
    use gpui::{App, Context, SharedString};
    use gpui_luma::controls::tree_view::{TreeDropProposal, TreeNode, TreeView, TreeViewDragDrop};
    use gpui_luma_look_radix as radix;

    #[derive(Default)]
    struct Workspace { dirty: bool, error: Option<String> }

    // The host transaction prepares and applies both snapshots and transferred
    // selection/expansion state, returning whether data changed. On error it
    // must leave both trees unchanged. This callback runs synchronously.
    fn build(
        cx: &mut Context<Workspace>,
        apply_move: impl Fn(&TreeDropProposal<()>, &mut App) -> Result<bool, SharedString> + 'static,
    ) -> TreeView<()> {
        let config = TreeViewDragDrop::new(cx.entity_id(), move |proposal, _, cx| {
            if proposal.node_ids().iter().any(|id| id.as_ref() == "root") {
                proposal.rejected("Workspace root cannot move", cx);
                return;
            }
            match proposal.validate(cx).and_then(|()| apply_move(&proposal, cx)) {
                Ok(changed) => proposal.committed(changed, cx),
                Err(error) => proposal.rejected(error, cx),
            }
        }).drag_selected(true);
        radix::TreeView::new("workspace")
            .items([TreeNode::new("root", "Workspace", ())])
            .drag_drop(config)
            .on_dropped(cx, |owner, _, _, _, _, _, changed, cx| {
                owner.dirty |= changed;
                owner.error = None;
                cx.notify();
            })
            .on_drop_rejected(cx, |owner, _, _, _, _, error, cx| {
                owner.error = Some(error.to_string());
                cx.notify();
            })
            .spawn(cx)
    }
}

Committed changes also support shared drop-layout motion, including duration settings, reduced motion and documented virtualization/transfer limits.
