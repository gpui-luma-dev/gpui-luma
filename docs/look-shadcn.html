Luma/Look-shadcn

Look-shadcn

Shadcn styling on SDK controls.

Use it

Shadcn · integration snippet
use gpui::{Context, Entity};
use gpui_luma::controls::button::Button;
use gpui_luma::infra::presenter::HasPresenter;
use gpui_luma_look_shadcn as shadcn;

struct Example { save_requests: usize }

fn save_button(cx: &mut Context<Example>) -> Entity<Button> {
    shadcn::Button::new("save").primary().label("Save")
        .on_click(cx, |app, cx| {
            app.save_requests += 1;
            cx.notify();
        })
        .spawn(cx)
}

Inside an initialized view constructor. Store and render the returned entity.

Control support

Support describes the styling this Look supplies for the documented SDK controls. SDK behavior and events are shared across Looks.

Supported: a Look builder, theme, or template is available; the notes identify how to use it. Partial: styling is available only through another control. Not provided: no styling adapter is supplied. Styling not needed: use the SDK utility directly; its child controls or scrollbar may still need styling.

Variants and customization options belong to each Look. Names in different Looks do not guarantee matching appearances. See the Look public API for exports.

Look selection

Builders use the application’s global ShadcnLook, or the built-in fallback. No .look(...) call is required.

Use .look(&custom_look) only to bind a particular instance, such as a fork or preview.

Customize

Start with builder variants. Use content presenters and template modifiers for local changes; use a template override for a different structure.
