A row of commands and embedded controls.

Basic use

Radix · integration snippet
use gpui::{Context};
use gpui::prelude::*;
use gpui_luma::controls::toolbar::ToolbarItem;
use gpui_luma::infra::presenter::HasPresenter;
use gpui_luma_look_radix as radix;

struct Example {
    control: gpui_luma::controls::toolbar::Toolbar,
    last_command: String,
}

impl Example {
    fn new(cx: &mut Context<Self>) -> Self {
        let save = radix::Button::new("save").label("Save").spawn(cx);
        let control = radix::Toolbar::new("editor")
            .item(ToolbarItem::command_button("save-item", save, cx))
            .on_click(cx, |app, id, cx| {
                app.last_command = id.to_string();
                cx.notify();
            })
            .spawn(cx);

        Self { control, last_command: String::new() }
    }
}

Integration snippet, checked against the current SDK and Radix crates. cx is the initialized owner context. The control retains its callbacks; callback owners are held weakly. Render self.control.clone() in the owner’s view.

SDK behavior & customization

Compose buttons, toggles, and fields; the toolbar owns its navigation policy.

Relevant contracts: ToolbarItemRenderModel, ToolbarRenderModel, ToolbarTemplateModifier, ToolbarTemplate.

Use the module’s template contract for structural changes. Builder modifiers and item templates vary by control.

Events

Callbacks follow the existing SDK event stream. Registrations append, hold the owner weakly, and live until the control is released. cx.notify() requests an owner redraw. Compound payloads are borrowed; scalar values are passed by value.

Event / payloadCallback
Click { id: SharedString }.on_click(cx, |app, id, cx| { … })
Change { id: SharedString, value: ToolbarValue }.on_value_changed(cx, |app, id, value, cx| { … })

Use .on_event(cx, |app, event, cx| { … }) for all events. Factory-created controls support the same callbacks through ToolbarEventExt. Existing cx.subscribe observers remain supported.
