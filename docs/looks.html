Luma/Lookless

Lookless

Control behavior belongs to the SDK. Presentation belongs to the template.

Similar controls, distinct visual systems

Luma separates interaction from visual design. SDK controls manage state, keyboard and pointer input, focus, and semantic events. Templates define the rendered structure and appearance. This lets applications change a control’s presentation while preserving its interaction contract.

A Look packages templates, colors, typography, and metrics into a consistent design system. Look-shadcn and Look-radix provide similar controls, each shaped by its own design conventions. Their control coverage and configuration APIs can differ.

Customize a template

Implement the control’s template trait and install it with .template(...). The template receives a render model containing the current state. This small button template reuses the built-in renderer for state and focus feedback, then adjusts its geometry:

Rust · Custom button template
use std::sync::Arc;
use gpui::{App, Div, Stateful, Window, prelude::*, px};
use gpui_luma::controls::button::{
    Button, ButtonRenderModel, ButtonTemplate, default_button_template,
};
use gpui_luma::infra::presenter::HasPresenter;

struct CompactButtonTemplate;

impl ButtonTemplate for CompactButtonTemplate {
    fn render(
        &self,
        model: &ButtonRenderModel<()>,
        window: &mut Window,
        cx: &mut App,
    ) -> Stateful<Div> {
        // Retain the default state and focus visuals; adjust the geometry.
        default_button_template().render(model, window, cx)
            .min_w(px(96.0))
            .rounded(px(6.0))
    }
}

let save = Button::new("save")
    .label("Save")
    .template(Arc::new(CompactButtonTemplate))
    .on_click(cx, |app, cx| { app.save_requests += 1; cx.notify(); })
    .spawn(cx);

Integration snippet: cx is the owning view’s context; the view has a save_requests: usize field.

The click callback remains application logic. The template controls presentation; add behavior functions only when the interaction itself needs to change. See control specialization for a fuller example.

Use a shared Look

For a complete visual system, start with Look-shadcn or Look-radix, or create your own Look. Look builders resolve the application’s global Look; .look(&custom_look) provides an explicit override.

A Look is optional. The SDK can render controls on its own using the built-in appearance defaults. Use those defaults directly, customize a template, or adopt a Look when you need a shared visual system.
