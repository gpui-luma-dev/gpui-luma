Getting Started

Native controls with reusable behavior and replaceable presentation.

Important: sample apps

Explore the runnable apps alongside these docs. The repository includes workbenches for both Looks, a native chart gallery, and sample application shells. Their source shows how controls, themes, layouts, and events fit together in a complete application.

From the repository root, run one of the following commands. These launch native desktop applications; use the repository’s native build prerequisites.

Sample / sourceWhat to exploreRun
Luma StudioShadcn control examples and theme inspection. See Look-shadcn.cargo run -p luma-studio
Radix StudioRadix style guide, palette editor, and control previews. See Look-radix.cargo run -p luma-radix-studio
Plot VizLine, area, bar, pie/donut, radar, and radial chart galleries using the Radix Look. See Plots.cargo run -p luma-plot-viz
Detached shellA sample application shell with detached-style regions.cargo run -p luma-shell-detached -- default
Split-titlebar shellA sample shell with a split titlebar layout.cargo run -p luma-shell-split-titlebar -- default
VS Code shellA workbench-style shell with configurable workspace regions.cargo run -p luma-shell-vscode -- default
Shell 2026An alternative application shell and titlebar composition.cargo run -p luma-shell-2026 -- default

Shell themes: only the four shell commands above take default or a built-in Shadcn theme ID, such as retro-arcade, after --. Radix Studio and Plot Viz use Radix palettes; they do not accept Shadcn named CSS themes.

Release builds: Cargo’s --release option applies to all these apps. For example, use cargo run --release -p luma-plot-viz or cargo run --release -p luma-shell-vscode -- default.

What you get

Controls, layouts, focus and input handling, semantic events, and customizable templates. Shadcn and Radix Look crates provide ready-to-use styling.

Philosophy & design

The SDK owns behavior. Templates own presentation. Looks configure a visual system. Customize content, modify a template, or replace it without rebuilding the control’s interaction logic.

A small complete app

A single window with a native Shadcn button. In a local workspace package, use these dependencies:

Cargo.toml · workspace package
[package]
name = "luma-hello"
version = "0.1.0"
edition = "2024"

[dependencies]
gpui.workspace = true
gpui_platform.workspace = true
gpui-luma.workspace = true
gpui-luma-look-shadcn.workspace = true
src/main.rs
use gpui::{prelude::*, Context, Entity, Render, Window, WindowOptions, div};
use gpui_luma::controls::button::Button;
use gpui_luma::infra::presenter::HasPresenter;
use gpui_luma_look_shadcn as shadcn;

struct Hello {
    button: Entity<Button>,
    saves: usize,
}

impl Hello {
    fn new(cx: &mut Context<Self>) -> Self {
        let button = shadcn::Button::new("hello")
            .primary().label("Hello, Luma")
            .on_click(cx, |app, cx| {
                app.saves += 1;
                cx.notify();
            })
            .spawn(cx);
        Self { button, saves: 0 }
    }
}

impl Render for Hello {
    fn render(&mut self, _: &mut Window, _: &mut Context<Self>)
        -> impl IntoElement
    {
        div().size_full().flex().flex_col().gap_2().items_center().justify_center()
            .child(self.button.clone())
            .child(format!("Saved {} times", self.saves))
    }
}

fn main() {
    gpui_platform::application().run(|cx| {
        if let Err(error) = gpui_luma::init(cx) {
            eprintln!("Initialization failed: {error}");
            return;
        }
        gpui_luma::focus::bind_default_focus_keys(cx);
        gpui_luma::key_handling::bind_default_control_keys(cx);
        if let Err(error) = cx.open_window(WindowOptions::default(), |_, cx| {
            cx.new(Hello::new)
        }) {
            eprintln!("Window creation failed: {error}");
            return;
        }
        cx.activate(true);
    });
}

Add the package to the workspace members. This app was checked against the current crates. Platform setup follows the repository’s native applications.
