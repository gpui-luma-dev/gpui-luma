Eventing review

What the SDK publishes, where the vocabulary drifts, and which silences are real gaps. Scope is crates/sdk control and infra events. Look crates, plot, and color controls are out of scope.

Verdict

The SDK has a usable event surface: almost every interactive control is an EventEmitter, most enums are #[non_exhaustive], and value changes are generally distinct from focus, hover, and enabled transitions. The problem is consistency, not absence. The same user gesture is named, shaped, and delivered differently depending on which control owns it. A subscriber who has learned one control cannot predict the next.

38 public event types

33 GPUI emitters, one returned batch (ListBoxEvent), one callback (TooltipEvent), and a handful of aliases and internal machines.

Three delivery channels

cx.emit, ListBoxUpdate.events, and Tooltip::on_event. Hosts cannot subscribe the same way to every control.

One vocabulary, many dialects

Change, Select, Click, Activate, Complete, and Submit all mean “the user committed something.” Payloads and pairing rules differ.

Owner-bound callbacks

SDK and Look builders now expose .on_event(cx, |app, event, cx| { … }) and named callbacks for their existing events. Change maps to .on_value_changed; focus, selection, open, and drag events retain their semantic names. Each control page lists the exact arguments.

Handlers append in registration order and hold the application owner weakly. The emitting control retains them until release. Existing cx.subscribe observers still work. Factory-created entities expose the same callbacks through their SDK *EventExt trait.

List Box retains host-delivered transactions. Tooltip retains attachment lifecycle callbacks, with .on_shown and .on_hidden. These helpers do not change which events a control emits or whether a programmatic setter emits.

Published catalog

Variants below are the public enums. Notes call out pairing and what a subscriber actually observes.

Command and choice

  • CommandEvent / ButtonEvent — Click, FocusChanged, EnabledChanged, HoverChanged. Pointer clicks that GPUI marks as keyboard are ignored; keyboard activation goes through ActivateControl and still emits Click. No modifier or source payload.
  • CheckboxEvent — Change { checked } plus the three interaction variants. Forwarded from the inner button. No indeterminate state exists.
  • SwitchEvent — Change { on } plus interaction.
  • ToggleEvent — Change { selected } plus interaction.
  • RadioButtonEvent — Change { selected } plus interaction. A lone radio does not know its group.
  • ControlGroupEvent — Activate { activated_id }, Change { changed_id, selected, selected_ids }, ItemBoundsChanged, FocusChanged, ItemFocused. A selection change emits Change and then Activate. Re-activating the current selection emits Activate alone. Bounds fire from layout.
  • RadioGroupEvent — Change { value: Option<SharedString> }, Activate { value }, FocusChanged, ItemFocused. Mapped from the group. Change keeps only selected_ids.first(). ItemBoundsChanged is dropped. EnabledChanged is not on the inner enum, so it cannot be forwarded.
  • ToolbarEvent — Click { id }, Change { id, value: Bool | String }. Child button clicks, toggle/menu/selector/text changes are collapsed into these two. Child focus, hover, enabled, open, and dismiss are dropped. Item on_click / on_change closures run as well as the emit.

Text

  • TextFieldEvent — Change { value: String }, Submit { value }, FocusChanged, EnabledChanged. Change fires on user edits, cut, and paste. set_value is silent. Hover and invalid are visual. Validator failure updates invalid and does not emit.
  • TextAreaEvent — Change, FocusChanged, EnabledChanged. Same programmatic-silence rule. No Submit.
  • TextSelectionEvent — adapter used inside combo, autocomplete, and search: Change, Submit, FocusEnter, FocusLeave. EnabledChanged is discarded. This is the only focus API that uses enter/leave unit variants.

Range and scroll chrome

  • SliderEvent — Change { thumb_id, value }, Release, DragStart, DragEnd { thumb_id, value }, ThumbAdded, ThumbRemoved, ThumbSelected, plus focus, hover, enabled. Pointer move emits Change continuously. Pointer up emits Release and DragEnd with the same value. Keyboard step emits Change then Release, with no drag pair. set_value passes emit: false.
  • ScrollbarEvent — Change { value }, DragStart, DragEnd { value }, focus, hover, enabled. No Release twin.
  • ScrollContainer — no event enum. Offset changes are methods. The inner Scrollbar still emits if the host subscribes to it directly.

Selection popups

  • SelectorEvent — Change { item_id, label }, FocusChanged, OpenChanged { open }, Dismiss. Selecting an item emits OpenChanged { open: false } and does not emit Dismiss. Dismiss is the cancel path. Re-selecting the current item closes the menu and skips Change.
  • AutocompleteEvent, ComboBoxEvent, SearchSelectorEvent — identical variants: Change { query }, Select { item_id, label }, Complete { item_id, label }, Clear, FocusChanged, OpenChanged, Dismiss. Complete is Select when an internal exact_complete flag is set. Both represent a chosen item. Highlight moves are silent.
  • SelectionPanelEvent — HoverChanged { visible_index }, ActivateRow { source_index, visible_index, item_id }, ActiveIndexChanged, FocusChanged, OpenChanged.
  • SelectionEvent — Focus, Blur, Escape, Submit, MoveNext, MovePrevious, Clear. Input to the shared behavior object, not a control subscription.

Overlay

  • PopupMenuEvent — ActionClick, Select { item_id, label }, OpenChanged, Dismiss, focus, hover, enabled. Close emits OpenChanged { open: false }. Dismiss is an extra event on the dismiss path only.
  • ContextMenuEvent — Select, OpenChanged, Dismiss, focus, hover, enabled. No ActionClick.
  • PopoverButtonEvent — OpenChanged { open }. Not non_exhaustive. The button does not forward panel focus or dismiss.
  • PopoverPanelEvent — OpenChanged, Dismiss, FocusChanged.
  • OverlayWindowEvent — Opened, Dismissed. Edge events, no boolean, no focus.
  • TooltipEvent — Shown, Hidden. Callback only. Not non_exhaustive.

Navigation

  • TabsEvent — Change { tab_id, label }, Activate, Reactivate, DropdownRequested { tab_id, label, bounds }, ItemBoundsChanged, FocusChanged, ItemFocused. A new tab emits Change and then Activate. Clicking the already active tab emits Reactivate and then Activate. Dropdown tabs also emit DropdownRequested on that path. Deselect (selected: false) is dropped.
  • AccordionEvent — ExpandedChanged { item_id, expanded }, FocusChanged, ItemFocused, ItemHoverChanged, EnabledChanged. Single mode can emit a collapse for the previous item and an expand for the new one. There is no separate activate event.
  • SidebarEvent — PresentationChanged, Select { id }, ItemFocused, HoverChanged { id: Option<SharedString> }, SubMenuToggle { id, open }, EnabledChanged.
  • SidebarPanelEngineEvent — Activate { node_id, label }, BranchExpandedChanged, CollapsedChanged, FocusChanged, ItemFocused, ItemHoverChanged, RailSubmenuOpenChanged, EnabledChanged. The public sidebar drops FocusChanged and CollapsedChanged. Item hover and rail-submenu open are both republished as SidebarEvent::HoverChanged.
  • PagerEvent — PageChanged { page }, PageSizeChanged, PageSizeOpenChanged { open }, EnabledChanged. No focus or hover.

Collections

  • TableEvent — RowDrag(DragDropEvent), SelectionChanged { selected_indices }, SelectedKeysChanged { selected_keys }, ActiveIndexChanged, PageChanged, PageSizeChanged, ScrollChanged { top_index }, FocusChanged, RowHoverChanged { index, hovered }, EnabledChanged. Index selection can fire on a reorder when key membership did not. Key events require set_row_key and fire only when membership changes. Enter/Space selects the active row and does not emit an activation event. PagingTableControl clones every TableEvent outward and also writes page changes back into the table.
  • TreeViewEvent<T> — DragDrop(TreeViewDragEvent), NodeActivated { node_id, data }, SelectionPolicyChanged, NodeExpanded, NodeCollapsed, SelectionChanged { selected_ids: HashSet }, ActiveNodeChanged, ScrollChanged, FocusChanged, RowHoverChanged { node_id, index, hovered }, EnabledChanged. The selection set has no order.
  • TreeViewDragEvent — Started, Dropped, Rejected, Ended { reason }. Not non_exhaustive. Narrower than DragDropEvent: no ItemsRemoved / ItemsAdded / ItemsReordered split, and its own TreeDragEndReason.
  • ListBoxEvent<K> — SelectionPolicyChanged, SelectionChanged { selected: Vec<K>, active }, ActiveItemChanged, ItemActivated { key }, ProjectionChanged { visible_count }, FocusChanged { is_focused }. Returned in a Vec on ListBoxUpdate, which also carries reveal: Option<K> for host-owned scrolling. One transaction can emit selection and active together.
  • DragDropEvent<S, K> — DragStarted, ItemsRemoved, ItemsAdded, ItemsReordered, Dropped, DropRejected, DragEnded { reason }. Domain-independent. Table nests it. Tree reimplements a cousin instead of reusing it.

Layout

  • SplitViewEvent — ResizeStart, SidebarWidthChanged { width }, ResizeEnd { width }, CollapsedChanged, SeparatorHoverChanged, EnabledChanged. Width is absolute. No focus event; the separator is not a focus stop in this enum.
  • ResizablePanelsEvent — ResizeStart, SizesChanged { sizes_px }, ResizeEnd, PanelHiddenChanged { panel_index, hidden }, PanelRegionHiddenChanged { region, panel_index, hidden }, HandleFocusChanged, HandleHoverChanged, EnabledChanged. SizesChanged includes animation frames and parent remeasurement, deferred off the prepaint path. A hidden panel with an id emits both hidden variants.
  • DockSplitterEvent — ResizeStart, Resize { total_delta }, ResizeEnd, focus, hover, enabled. The live payload is a delta, not a size.

Reconsider

These are published and working. They are the parts most likely to produce duplicate work, missed signals, or subscriber loops.

VocabularyCommit has six names

Click, Change, Select, Activate, Complete, and Submit overlap. Selector’s commit is Change. The three text pickers use Select or Complete for the same choice. Popup menu splits ActionClick and Select. Tabs fires Change and Activate for one click, and Reactivate plus Activate for a second click on the current tab. Control group always follows a real Change with Activate.

Pick one commit name per kind of control: value (Change), invocation (Click or Activate), and choice (Select). Keep Submit for text commit. Make Complete a documented mode of Select, or fold the flag into the payload (exact: bool), so subscribers stop matching both variants.

PairingClose is two events, and only sometimes

Menus, selector, and the text pickers emit OpenChanged { open: false } on every close. They emit Dismiss only when the close is a cancel. Selecting an item closes without Dismiss. Overlay window uses a third dialect: Opened and Dismissed, with no boolean and no “closed because committed” distinction. Popover button publishes only OpenChanged.

Standardize on OpenChanged { open } for the boolean, and a separate Dismiss only for cancel. Document that successful selection is OpenChanged { open: false } without Dismiss. Map overlay window onto that pair, or document it as the exception in one place.

PairingSlider pointer-up emits the value twice

Pointer up emits Release and DragEnd with the same thumb_id and value. Keyboard nudges emit Change and Release and skip the drag pair. Programmatic set_value emits nothing. Scrollbar has Change / DragEnd and no Release.

Change should stay the live value. One terminal event should mean “gesture finished.” Release and DragEnd currently compete for that role. Keep DragStart / DragEnd for gesture brackets and let Release be the commit, including keyboard, or drop Release and teach keyboard to emit DragEnd. Do not keep both with identical payloads.

ChannelLayout traffic shares the semantic enum

ControlGroupEvent::ItemBoundsChanged and TabsEvent::ItemBoundsChanged fire from layout. ResizablePanelsEvent::SizesChanged fires on animation frames and on parent remeasurement, which the enum documents. Table and tree ScrollChanged and row-hover variants are high frequency next to selection. Radio group already drops bounds. Tabs still forwards them.

Bounds, per-frame sizes, scroll offsets, and hover belong on a presentation channel or a sampled callback. Semantic subscribers should be able to ignore them without matching them away. If bounds stay, they should not be required to retarget a tab indicator — that can stay internal, which tabs already does before it re-emits.

IdentitySelection payloads do not match

List box reports an ordered Vec of keys plus active in one event, and a separate ActiveItemChanged. Table reports ordered indices and, when keyed, an ordered key vec as a second event. Tree reports an unordered HashSet and a separate active id. List box focus is is_focused; every other control uses focused.

Collection commits should carry ordered keys and the active key in one event. Indices are a view concern and go stale across sort, filter, and paging — table already says this in its module docs, then still leads with SelectionChanged { selected_indices }. Tree’s set should become a Vec in display order, matching list box and SelectedKeysChanged.

TranslationSidebar flattens the engine and overloads hover

The engine publishes focus, collapse, per-item hover, and rail-submenu open as distinct variants. The public sidebar drops focus and collapse. It turns both item hover and RailSubmenuOpenChanged into HoverChanged { id: Option<SharedString> }. A None id means “hover ended,” and a Some from the rail path means “submenu target,” using the same variant.

Forward FocusChanged and CollapsedChanged, or delete them from the engine if the host is not allowed to see them. Give the rail submenu its own event. Hover should stay { id, hovered }, consistent with accordion and the engine.

TranslationRadio group throws away multi-select detail

The inner Change carries changed_id, selected, and the full selected_ids. The radio event keeps selected_ids.first() as Option. That matches exclusive radios and misrepresents a multi group. Tabs, by contrast, keep the specific id and also keep bounds the radio group drops.

If radio group is exclusive, say so in the event (Change { id }) and stop implying a full selection set. If multi is legal, forward selected_ids.

DragTwo drag lifecycles for one infra type

DragDropEvent is the shared keyed lifecycle: started, removed, added, reordered, dropped, rejected, ended. Table embeds it. Tree defines TreeViewDragEvent with a different reason enum and a single dropped/rejected pair, then wraps that in TreeViewEvent::DragDrop. End reasons are not interchangeable (Transferred / Reordered versus MovedWithinTree / MovedAcrossTrees).

Tree can keep domain fields (TreeDropLocation) on a payload inside DragDropEvent, or document the tree enum as a projection and map reasons in one function. A third shape — slider and scrollbar DragStart / DragEnd — is fine for a scalar thumb. It should not grow a third copy of rejected/cancelled.

ResizeThree live payloads

Split view emits absolute sidebar width. Dock splitter emits total_delta. Resizable panels emit the full sizes_px vector, including frames that are not a user gesture. Subscribers that persist layout cannot share a helper.

Live and terminal events should carry absolute sizes. Deltas can be derived. SizesChanged during animation should be opt-in or named so a persist subscriber can listen only to ResizeEnd.

DeliveryList box is a different product shape

List box is the most careful collection model: transactions, ordered keys, activation distinct from selection, projection changes, and a reveal request instead of a fake scroll event. It is also the only collection that refuses EventEmitter. Table and tree emit immediately, so a subscriber can observe a half-updated sibling. List box asks the host to deliver the batch after state is committed.

Either give ListBoxControl an emitter that flushes ListBoxUpdate.events in order, or treat the batch as the collection pattern and stop adding one-off emits on table and tree. Mixing them means look code and app code learn two subscription styles for the same gesture.

APIA few enums cannot grow

PopoverButtonEvent, TooltipEvent, and TreeViewDragEvent are exhaustive. Everything else a host matches is non_exhaustive. Adding dismiss or focus to the popover button, or a drag phase to the tree, is a breaking change today and a warning elsewhere.

LoopPaging table re-emits and writes back

PagingTableControl subscribes to the table and emits the same TableEvent values. It also subscribes to the pager and calls set_page / set_page_size on the table, which emit again. Selection updates push a summary string into the pager. The comment on table selection says setters emit once so owners can feed state back. The paging wrapper is a second owner inside that loop.

Page changes that originated from the pager should not re-enter set_page if the table is already on that page. The table module already claims setters emit only on difference; the wrapper should rely on that and should not be the place hosts subscribe if they also subscribe to the inner table.

Missing

Gaps a host hits when wiring the control. Interaction variants that button-family controls already have, and that composites drop, are listed first because they are inconsistent rather than new product surface.

ForwardingEnabled, focus, and hover die at composite boundaries

  • Toolbar publishes click and change only. A disabled toolbar item, a focused text item, or an open menu is invisible to the toolbar subscriber.
  • Selector, combo box, autocomplete, and search selector have focus and open, and no EnabledChanged. The choice controls they sit next to all emit it.
  • Radio group and tabs have focus and no enabled event, because control group itself has no EnabledChanged.
  • Popover button does not forward PopoverPanelEvent::Dismiss or FocusChanged.
  • Sidebar drops engine focus and collapse.
  • Text field hover updates state and does not emit. Text area has no hover event at all.

Composites should forward the interaction trio when the inner control already emits it. Hosts that only need the commit can ignore the variants; hosts that sync chrome cannot invent them.

TableActivation selects and stops

Enter, Space, and row click call select_index. Tree and list box both emit an activation distinct from selection (NodeActivated, ItemActivated). A table host that should open a row has to treat “selection became this single index” as a click, which is wrong for keyboard navigation that also changes selection, and wrong for extended selection.

Add RowActivated { index, key } on the explicit activate path. Keep selection events for membership changes.

TextInvalid and submit are uneven

Both text controls recompute invalid from a validator on edit and on set_value, then only repaint. There is no InvalidChanged. Text area has no Submit, so a multiline field cannot share the text field’s commit path. Neither control publishes selection or caret changes; that is acceptable until a host needs a live character count or a collaborator caret. Invalid is not optional in the same way: the control already knows, and the host that supplied the validator often needs the bit for a form.

ScrollThe container does not speak

ScrollContainer owns offset, smooth scrolling, and wheel policy. Subscribers must attach to the inner scrollbar’s Change, which is a normalized thumb value, or poll vertical_offset(). Table and tree already emit ScrollChanged { top_index }. A viewport event with offset and maximum would match those collections and let auto-hide chrome stay inside the container.

StepperStep changes are method calls only

set_current_step and set_step_state notify and do not emit. If the stepper stays a display driven by the host, silence is correct. If a step becomes clickable, there is nowhere to put StepActivated. Decide that before adding pointer targets. Progress is in the same position: set_value is host-driven, and an event would only echo the caller.

Slide panelNot an entity

Slide panel is app-owned state plus render helpers and resize handler structs. Open, dismiss, and resize never become events. That matches the module comment. It also means the overlay family has four lifecycle dialects: menu OpenChanged+Dismiss, window Opened/Dismissed, popover OpenChanged, and slide-panel callbacks. If slide panel remains a helper, say so next to overlay window so hosts do not look for an emitter.

PickerHighlight is invisible

Combo box, autocomplete, and search selector move a highlighted row on the arrow keys and emit nothing until submit, clear, or open changes. Selection panel emits ActiveIndexChanged for the same idea. A host rendering a side preview of the highlighted item has to read the behavior object or duplicate keyboard handling.

ButtonClick has no origin

Pointer and keyboard both become Click with an empty payload. That is a good default. It blocks the few hosts that need to distinguish them (opening a menu on pointer versus activating the primary command on keyboard, which split button approximates by using a different control). A source field can wait until a real caller needs it. Do not add a parallel Press event without that caller.

Leave alone

KeepThese splits are doing work

  • Programmatic setters that do not emit (TextField::set_value, Slider::set_value) let a subscriber write state back without a loop. Table’s module docs describe the same rule. Preserve it when adding events.
  • Dismiss meaning cancel, separate from close-on-select, is the right distinction. The fix is to apply it everywhere, not to remove it.
  • List box’s batch plus reveal is the clearest collection contract in the crate. Copy it; do not replace it with ad-hoc emits.
  • SelectionEvent staying off the public subscription path is correct. The three pickers should keep sharing that machine.
  • Button Click with no geometry is the right command event. Focus, hover, and enabled already cover chrome.
  • Accordion ExpandedChanged as the only commit is enough while items are disclosure, not navigation.
  • Progress and frame staying silent is correct. They display host state.
  • Dual hidden events on resizable panels are an explicit compatibility shim. Collapse them when index-based subscribers are gone, and not before.

Suggested sequence

  1. Write the vocabulary down as crate docs, not a new trait: commit, focus, hover, enabled, open, dismiss, drag bracket. Map each current variant onto it so new controls stop inventing names.
  2. Stop double payloads. Slider pointer-up, tabs Reactivate+Activate, and control-group Change+Activate each need one canonical event for “this is the commit.”
  3. Move per-frame and bounds traffic off the default semantic enum, starting with SizesChanged during animation and ItemBoundsChanged on tabs.
  4. Align collection selection on ordered keys. Add table RowActivated. Decide whether list box gains an emitter or table/tree gain a batch.
  5. Forward interaction events at toolbar, selector family, radio group, popover button, and sidebar, or delete the inner variants nobody is allowed to see.
  6. Add InvalidChanged on both text controls. Add Submit to text area only if a caller needs Enter-to-commit; otherwise document that text area has no submit key.
  7. Mark PopoverButtonEvent, TooltipEvent, and TreeViewDragEvent non_exhaustive before the next variant.
Do not introduce a single SDK-wide event enum. The controls are different types on purpose. The win is a shared set of names and payload shapes, applied per control, with layout noise kept off the path hosts match on.
