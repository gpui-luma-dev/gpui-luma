# Issue #1: Automated Control Exposition Documentation (`cargo xtask gen-docs`)

## Overview & Problem Statement

Luma Studio control exposition screens (such as `apps/luma-studio/src/studio/controls/control_exposition/stepper.rs`) display itemized API documentation tables (`PublicInterfaceSpec`) covering three surface layers:
1. **Look Factories**: `ShadcnLookControlExt` methods from `crates/look-shadcn`.
2. **Builder Methods**: `*Builder` configuration methods from `crates/sdk`.
3. **Control Methods/Getters**: `*Control` entity runtime methods from `crates/sdk`.

Currently, these specs are hardcoded as static string arrays (e.g., `LOOK_INTERFACE_SPECS`, `BUILDER_INTERFACE_SPECS`, `CONTROL_INTERFACE_SPECS`). Because Rust lacks runtime reflection, method renames, signature changes, or doc additions in SDK crates cause Studio UI documentation to silently drift out of sync.

---

## Technical Solution: `cargo xtask gen-docs`

To eliminate brittle hardcoded strings without impacting standard developer compile times, we introduce an **on-demand CLI code generator** using the standard Rust `xtask` pattern.

### 1. Workspace Crate Layout

```
gpui-luma/
├── .cargo/
│   └── config.toml                  # Alias: xtask = "run --package xtask --"
├── xtask/
│   ├── Cargo.toml                   # Dependencies: syn, quote, prettyplease, anyhow
│   └── src/
│       ├── main.rs                  # CLI entry point (`cargo xtask gen-docs`)
│       ├── parser.rs                # AST parsing routines for SDK & Look crates
│       └── codegen.rs               # Code generator for PublicInterfaceSpec arrays
└── apps/luma-studio/
    └── src/
        └── studio/
            └── controls/
                └── control_exposition/
                    └── generated_specs/ # Commited generated spec files
```

### 2. AST Extraction Capabilities (`syn`)

The `xtask` CLI parses Rust AST directly from source files in `crates/sdk` and `crates/look-shadcn`:

* **`ShadcnLookControlExt` Trait & Impl Blocks**:
  * Parses `crates/look-shadcn/src/**/*.rs`.
  * Identifies factory entry points (e.g., `look.stepper(id, step_count)`).
  * Assigns group: `Look · gpui_luma_look_shadcn::ShadcnLookControlExt`, surface: `"factory"`.

* **`*Builder` & `*Control` Impl Blocks**:
  * Parses `crates/sdk/src/controls/**/*.rs`.
  * Identifies builder chain methods (surface: `"method"`) and entity runtime methods/getters (surface: `"method"` or `"getter"`).

* **`*Event` Enum Definitions**:
  * Parses `pub enum <Control>Event` definitions in `crates/sdk/src/controls/**/*.rs` (e.g., `ButtonEvent`, `SelectorEvent`, `StepperEvent`).
  * Extracts enum variants and their fields (e.g., `ButtonEvent::HoverChanged { hovered }`).
  * Generates `EVENT_SPECS: &[EventReferenceSpec]` arrays for event reference documentation.

* **Doc Comment (`///`) Extraction & Fallback Rules**:
  * Extracts doc comments (`///`) to populate the `notes` and `trigger` fields.
  * **Fallback Handling**: If `///` docs are missing on a public method or event variant, `xtask` derives fallback descriptions from naming conventions:
    * `set_<field>(val)` $\rightarrow$ `"Sets <field>."`
    * `is_<flag>()` / `<field>()` $\rightarrow$ `"Returns <field>."`
    * `look.<control>(...)` $\rightarrow$ `"Factory method for <Control>Builder."`
    * `<Control>Event::<Variant>` $\rightarrow$ `"Emitted on <Variant> interaction."`

### 3. Zero-Compile-Impact Workflow

* **Day-to-day Development (`0ms` Overhead)**:
  * Generated spec files are committed to git.
  * `cargo build` and `cargo run` in `apps/luma-studio` compile the generated files as standard static modules.
  * No `syn` parsing or `build.rs` execution occurs during normal app builds.

* **API Update Workflow**:
  * When updating SDK control signatures or adding new controls, run:
    ```bash
    cargo xtask gen-docs
    ```
  * Commit the updated SDK code and generated spec files together.

* **CI Enforcement**:
  * Run `cargo xtask check-docs` in CI (or git pre-commit hook) to ensure generated specs match current SDK signatures.

### 4. Generated Product & Luma Studio Consumption

#### A. Generated Artifact Format (`generated_specs/stepper.rs`)

`cargo xtask gen-docs` emits strongly typed Rust constants into `apps/luma-studio/src/studio/controls/control_exposition/generated_specs/`:

```rust
// AUTO-GENERATED BY `cargo xtask gen-docs` — DO NOT EDIT MANUALLY
use crate::studio::controls::control_exposition::model::PublicInterfaceSpec;

pub const LOOK_INTERFACE_SPECS: &[PublicInterfaceSpec] = &[
    PublicInterfaceSpec {
        symbol: "look.stepper(id, step_count)",
        surface: "factory",
        notes: "Returns StepperBuilder with Shadcn template bound.",
    },
];

pub const BUILDER_INTERFACE_SPECS: &[PublicInterfaceSpec] = &[
    PublicInterfaceSpec {
        symbol: "current_step(n)",
        surface: "method",
        notes: "Initial active step; earlier steps derive Complete, later Incomplete.",
    },
];

pub const CONTROL_INTERFACE_SPECS: &[PublicInterfaceSpec] = &[
    PublicInterfaceSpec {
        symbol: "set_current_step(n)",
        surface: "method",
        notes: "Move the active step; clears workflow_complete.",
    },
];

pub const EVENT_SPECS: &[EventReferenceSpec] = &[
    EventReferenceSpec {
        event: "ButtonEvent::Click",
        trigger: "User click",
        notes: "Primary action triggered.",
    },
    EventReferenceSpec {
        event: "ButtonEvent::HoverChanged { hovered }",
        trigger: "Pointer enter/leave",
        notes: "Emitted when hover state transitions.",
    },
];

pub const PUBLIC_INTERFACE_GROUPS: &[(&str, &[PublicInterfaceSpec])] = &[
    ("Look · gpui_luma_look_shadcn::ShadcnLookControlExt", LOOK_INTERFACE_SPECS),
    ("StepperBuilder", BUILDER_INTERFACE_SPECS),
    ("StepperControl", CONTROL_INTERFACE_SPECS),
];
```

#### B. Exposition Consumption (`stepper.rs`)

Instead of maintaining 150+ lines of hand-written spec arrays, the control exposition file imports the generated module directly:

```rust
// In apps/luma-studio/src/studio/controls/control_exposition/stepper.rs
use super::generated_specs::stepper as generated_specs;

// In render / UI definition:
render_public_interface_block(cx, generated_specs::PUBLIC_INTERFACE_GROUPS)
```
