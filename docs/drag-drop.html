Drag and drop

The shared contract for keyed collection drag/drop in ListBox, Table, and TreeView.

Choose a control

Configure drag/drop once on the persistent SDK control or builder. Looks supply themed native sources, targets and previews while the SDK owns session admission and completion guards. Rebuilding a Look adapter reuses registrations; keep application collection state and controls across renders.

  • ListBox: host-owned keyed reorder and transfer, with automatic event routing in Shadcn and Radix.
  • Table: SDK-owned same-table row reordering, automatic commits and an optional host policy override; also available through PagingTable and Shadcn.
  • TreeView: host-owned subtree moves within or between trees, retaining hierarchy and destination locations; SDK, Shadcn and Radix.

The linked control pages contain setup, exact domain payloads, compatibility notes and a compiled integration example. Collection drag/drop is opt-in. Slider, scrollbar, splitter, resize-handle and text-selection drags retain their gesture-specific contracts.

Proposals and completion

on_drop handles a proposed operation. Validate the live session, current keys and application policy, prepare all affected snapshots, apply data and selection/state changes, then synchronously commit or reject. on_dropped observes an accepted, completed operation after all those changes. Use completion for notifications or persistence, rather than making the proposal handler do both jobs.

ListBox and TreeView hosts own transactions and report their outcome through proposal completion methods. Table validates and commits automatically unless set_row_drop_handler overrides that behavior. Unanswered synchronous handlers are rejected. Do not defer mutation or retain a proposal to complete it after the handler returns.

A valid no-op completes with changed=false and the end reason Unchanged; it emits no mutation phases. Rejection leaves data unchanged and has its own rejected/end outcome. Cancellation ends the source session without rejection or completion. A gesture that never reaches an admitted proposal, including a foreign scope, can cancel without emitting rejection. Completion, rejection and preview-release cancellation share one guard, so retained clones cannot finish a session twice.

Callback registration and ownership

Use on_event(cx, callback) for the control event stream, on_drag_drop(cx, callback) for its nested drag/drop lifecycle, and the named helpers below for individual phases. Aggregate and named callbacks coexist. Table retains on_row_drag as a compatible aggregate alias.

Register once on a persistent SDK control/builder; factory-created Table and TreeView entities also expose SDK event extension traits. ListBox handlers live on ListBoxControl, alongside its selection callbacks. The control owns callback registrations, holds the application owner weakly, and releases captures when the control is released. Capture owning entities weakly to avoid cycles. Retained native previews and proposals do not retain emitting controls.

Registrations append in order within a binding. Delivery occurs after the current control/owner borrow ends, permitting callbacks to update the emitting control. Separate subscriptions follow GPUI dispatch order. Callback arguments are the owner, payload fields in the table, and the owner context; compound payloads are borrowed for that callback only, while scalar values are copied. Clone borrowed values to retain them.

Lifecycle and payloads

The shared event is DragDropEvent<S, K>. Persistent ListBox and Table callbacks use EntityId collection identities; source and target identify controls rather than host entities or render-time elements. ListBox uses its configured key type K; Table uses SharedString. before=None is an append gap. TreeView projects every phase into its domain payloads, preserving locations and normalized subtree roots.

Scopes, validation and interaction

A scope admits cooperating surfaces. Use one shared scope for collections allowed to exchange compatible payloads; different scopes reject admission. Matching scope IDs alone do not make different control domains interoperable. ListBox also requires a shared key type, and TreeView a shared domain type. TreeView and Table perform their domain validation; ListBox hosts validate current keys and application policy in addition to proposal lifetime checks.

GPUI owns native gesture thresholds, hit testing and previews. SDK bindings provide keyed gaps and cancellation; Looks expose the applicable targets and auto-scroll behavior. Native preview release, including Escape cancellation through the SDK focus actions, closes an unfinished session. Embedded controls should use the SDK drag boundary so their clicks and native drags remain independent of the enclosing row.
