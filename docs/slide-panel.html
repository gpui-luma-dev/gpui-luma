An edge-anchored drawer.

Basic use

SDK · integration snippet
use gpui::{Context, KeyDownEvent};
use gpui_luma::controls::slide_panel::{
    SlidePanelState, SlidePanelSizeConfig, SlidePanelTopAnchor, SlidePanelOverlayHandlers,
};

struct Example {
    state: SlidePanelState,
    close_requests: usize,
}

impl Example {
    fn new() -> Self {
        Self {
            state: SlidePanelState::new(
                SlidePanelTopAnchor::WindowEdge,
                SlidePanelSizeConfig::new(320.0, 240.0, 600.0),
            ),
            close_requests: 0,
        }
    }

    // Pass these callbacks to render_slide_panel_overlay.
    fn handlers(cx: &mut Context<Self>) -> SlidePanelOverlayHandlers {
        SlidePanelOverlayHandlers {
            key_down: Box::new(cx.listener(|app, event: &KeyDownEvent, window, cx| {
                if event.keystroke.key == "escape" && app.state.handle_escape(window, cx) {
                    app.close_requests += 1;
                    cx.notify();
                }
            })),
            backdrop_mouse_down: Box::new(cx.listener(|app, _, _, cx| {
                if app.state.request_close() {
                    app.close_requests += 1;
                    cx.notify();
                }
            })),
        }
    }
}

Integration snippet, checked against the current SDK and Radix crates. cx is the initialized owner context. Keep spawned entities and subscriptions in the owning view.

SDK behavior & customization

App-owned state plus render templates, not a spawnable SlidePanel entity.

Application interaction

Slide Panel uses application-owned state and renderer handlers, not SlidePanelEvent. The owner’s close, backdrop, and resize handlers update SlidePanelState and request a redraw.
