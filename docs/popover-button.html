Popover Button

A trigger-owned popup surface.

Basic use

SDK · integration snippet
use gpui::{Context};
use gpui_luma::controls::popover_button::PopoverButtonEvent;
use gpui::{div, prelude::*};
use gpui_luma::controls::popover_button::PopoverButton;

struct Example {
    control: gpui::Entity<gpui_luma::controls::popover_button::PopoverButton>,
    details_open: bool,
}

impl Example {
    fn new(cx: &mut Context<Self>) -> Self {
        let control = PopoverButton::<()>::new("details")
            .trigger(|_, _| div().child("Details").into_any_element())
            .content(|_, _, _| div().child("More information").into_any_element())
            .on_event(cx, |app, event: &PopoverButtonEvent, cx| {
                let PopoverButtonEvent::OpenChanged { open } = event;
                app.details_open = *open;
                cx.notify();
            })
            .spawn(cx);

        Self { control, details_open: false }
    }
}

Integration snippet, checked against the current SDK and Radix crates. cx is the initialized owner context. The control retains its callbacks; callback owners are held weakly. Render self.control.clone() in the owner’s view.

SDK behavior & customization

Placement and popup lifecycle belong to the control; supply the popup content.

Relevant contracts: PopoverRenderModel.

Events

Callbacks follow the existing SDK event stream. Registrations append, hold the owner weakly, and live until the control is released. cx.notify() requests an owner redraw. Compound payloads are borrowed; scalar values are passed by value.

Event / payloadCallback
OpenChanged { open: bool }.on_open_changed(cx, |app, open, cx| { … })

Use .on_event(cx, |app, event, cx| { … }) for all events. Factory-created controls support the same callbacks through PopoverButtonEventExt. Existing cx.subscribe observers remain supported.
