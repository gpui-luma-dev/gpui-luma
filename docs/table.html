Table

look-shadcn

Records in rows and columns.

Supports drag and drop. See the shared DnD guide for lifecycle, callbacks, and transaction rules.

Basic use

SDK · integration snippet
use gpui::{Context};
use gpui_luma::controls::table::{self, TableSelectionMode};

struct Example {
    control: gpui::Entity<gpui_luma::controls::table::TableControl<String>>,
    selected_rows: Vec<usize>,
}

impl Example {
    fn new(cx: &mut Context<Self>) -> Self {
        let control = table::new_typed::<String>("records")
            .items(["Draft".to_string(), "Published".to_string()])
            .row_label(|row| row.clone())
            .selection_mode(TableSelectionMode::Single)
            .on_selection_changed(cx, |app, selected_indices, cx| {
                app.selected_rows = selected_indices.clone();
                cx.notify();
            })
            .spawn(cx);

        Self { control, selected_rows: Vec::new() }
    }
}

Integration snippet, checked against the current SDK and Radix crates. cx is the initialized owner context. The control retains its callbacks; callback owners are held weakly. Render self.control.clone() in the owner’s view.

SDK behavior & customization

SDK selection supports Single, Multiple, Extended, and None. Stable row keys matter for reordering and selection.

Relevant contracts: TableColumnRenderModel, TableRenderModel, TableHeaderTemplate, TableRowRenderModel.

Use the module’s template contract for structural changes. Builder modifiers and item templates vary by control.

Events

Callbacks follow the existing SDK event stream. Registrations append, hold the owner weakly, and live until the control is released. cx.notify() requests an owner redraw. Compound payloads are borrowed; scalar values are passed by value.

Drag/drop

See Drag and drop for the lifecycle, proposal/completion distinction, ordering, scopes, and callback ownership shared by these controls.

Set unique stable row keys with set_row_key, then enable set_row_reordering(true, cx). Table commits automatically; set_row_drop_handler overrides that transaction and must synchronously call commit_row_drop or reject_row_drop. Failed validation leaves the dataset unchanged.

SDK TableBuilder, PagingTableBuilder, TableEventExt (plain and paging entities), and Shadcn Table expose the shared named helpers. Their exact arguments are in the shared payload table with K=SharedString. The aggregate payload TableRowDragEvent aliases DragDropEvent<EntityId, SharedString>, nested in TableEvent::RowDrag; on_drag_drop is a compatible alias of on_row_drag.

Table currently supports same-table row reordering. Transfer-phase helpers filter the shared event type but do not enable cross-table transfer. Paging forwards the inner table events, whose source/target IDs identify that inner table.

Validate proposals and observe completion

This integration example is compiled by scripts/check_control_docs.py.

mod drag_drop_example {
    use gpui::{Context, Entity};
    use gpui_luma::controls::table::{TableBuilder, TableControl, TableReorderError, TableSelectionError};

    #[derive(Default)]
    struct Queue { dirty: bool, error: Option<String> }

    fn build(cx: &mut Context<Queue>) -> Result<Entity<TableControl<String>>, String> {
        let control = TableBuilder::new_typed("queue")
            .items(["Draft".to_string(), "Published".to_string(), "Review".to_string()])
            .row_label(|row| row.clone())
            .on_dropped(cx, |owner, _, _, _, _, changed, cx| {
                owner.dirty |= changed;
                owner.error = None;
                cx.notify();
            })
            .on_drop_rejected(cx, |owner, _, _, _, _, error, cx| {
                owner.error = Some(error.to_string());
                cx.notify();
            })
            .spawn(cx);
        control.update(cx, |table, cx| -> Result<(), String> {
            table.set_row_key(|row| row.clone(), cx).map_err(|error: TableSelectionError| error.to_string())?;
            table.set_row_reordering(true, cx).map_err(|error: TableReorderError| error.to_string())?;
            table.set_row_drop_handler(|table, proposal, _, cx| {
                if proposal.keys().iter().any(|key| key.as_ref() == "Published") {
                    table.reject_row_drop(proposal, "Published rows are locked", cx);
                } else {
                    // Failed validation already emits rejection. No second completion is needed.
                    let _ = table.commit_row_drop(proposal, cx);
                }
            });
            Ok(())
        })?;
        Ok(control)
    }
}
